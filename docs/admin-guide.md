# Руководство администратора

Установка, конфигурация и эксплуатация **Sanskrit SRV** (beta `0.2.x`).  
Работа в UI для экспертов — в [руководстве пользователя](user-guide.md).

---

## 1. Состав системы

| Процесс | Назначение |
|---------|------------|
| **API** (`uvicorn app.main:app`) | HTTP API, статический UI, JWT-auth, экспорт PDF/DOCX |
| **Worker** (`python -m app.worker`) | Очередь jobs: нарезка сканов + LLM (оцифровка, перевод, IAST, смысловая проверка) |
| **SQLite** | Пользователи, проекты, страницы, версии, usage (по умолчанию) |
| **storage/** | Исходные PDF, PNG страниц, экспорты |
| **Google AI Studio** | Маршрут по умолчанию: Gemini (скан картинкой; перевод — отдельная текстовая модель) |
| **Timeweb AI Gateway** | Опционально; эксперт вставляет свой ключ в кабинете и выбирает модель со зрением |
| **ProxyAPI** | Запасной шлюз Claude Opus / OpenAI (и при необходимости Gemini) |

Без запущенного **worker** загрузка PDF создаст проект, но страницы не оцифруются.

На текущем тестовом VPS (~1 ГБ RAM) — один API + один worker, без Postgres/Redis/Celery. Лимиты systemd: `MemoryMax` ~400 M API / ~550 M worker. Для **1.0** нужен апгрейд хоста — [§9](#9-апгрейд-сервера-к-10).

### Задачи проектов

| Задача (`task`) | Что делает | Откуда |
|-----------------|------------|--------|
| **digitize** | Скан PDF → HTML деванагари | Загрузка PDF (admin) |
| **translate** | Выверенный санскрит → русский по шаблону | Кнопка **Перевод на русский** в оцифровке |
| **transliterate** | Выверенный санскрит → IAST по шаблону | Кнопка **Транслитерация IAST** в оцифровке |

Правка санскрита в переводе или IAST пишется в связанную страницу оцифровки **новой версией** (снимок старого HTML, затем запись). В проекте IAST, режим **Текст**: **Правка по IAST** правит деванагари по строке IAST; **Правка оцифровки** явно переносит это в исходник. Массовые кнопки конвейера всегда с `open_only`: согласованные страницы не перезаписываются.

## 2. Этапы установки

### Вариант A — локально (разработка / проверка)

1. **Клон и Python**
   ```bash
   git clone git@github.com:kobyzev-yuri/sanskrit_srv.git
   cd sanskrit_srv
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -U pip
   pip install -r backend/requirements.txt
   ```

2. **Конфигурация**
   ```bash
   cp .env.example .env
   ```
   Заполните минимум: `JWT_SECRET`, `GEMINI_API_KEY` (см. [§3](#3-конфигурация)).

3. **Каталоги и БД**
   ```bash
   mkdir -p data storage
   cd backend
   export PYTHONPATH=.
   python -m app.cli init-db
   ```

4. **Первый admin**
   ```bash
   python -m app.cli user-create \
     --email admin@example.com \
     --password 'STRONG_PASSWORD' \
     --role admin \
     --name Admin
   ```

5. **Запуск двух процессов**
   ```bash
   # из backend/, PYTHONPATH=.
   uvicorn app.main:app --host 0.0.0.0 --port 8000
   # во втором терминале:
   python -m app.worker
   ```

6. **Проверка**
   ```bash
   curl -s http://127.0.0.1:8000/health
   ```
   Откройте http://127.0.0.1:8000 и войдите созданным admin.

### Вариант B — VPS (systemd, как на тестовом хосте)

Целевой каталог: `/opt/sanskrit_srv`.

1. Синхронизируйте код на сервер (вручную или через GitHub Actions — [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml)).  
   **Не** перезаписывайте на сервере `.env`, `data/`, `storage/`.

2. Один раз положите секреты:
   ```bash
   scp .env root@HOST:/opt/sanskrit_srv/.env
   chmod 600 /opt/sanskrit_srv/.env
   ```

3. На сервере:
   ```bash
   bash /opt/sanskrit_srv/deploy/remote_deploy.sh
   ```
   Скрипт: создаёт venv, ставит зависимости, ставит unit-файлы `sanskrit-srv` и `sanskrit-worker`, перезапускает службы, дергает `/health`.

4. Bootstrap admin (если ещё нет пользователей):
   ```bash
   cd /opt/sanskrit_srv/backend
   PYTHONPATH=. /opt/sanskrit_srv/.venv/bin/python -m app.cli user-create \
     --email admin@example.com --password '...' --role admin --name Admin
   ```

5. Проксируйте `:8000` через nginx/Caddy с HTTPS (по политике хоста). На слабом VPS порт 8000 часто режет ещё облачный файрвол панели — его тоже нужно открыть.

### Вариант C — Docker Compose (опционально)

[`docker-compose.yml`](../docker-compose.yml) поднимает только API-образ с монтированием репозитория. Worker в compose не описан — для полного контура удобнее вариант A/B. На слабом VPS предпочтителен systemd + SQLite (см. комментарий в compose).

## 3. Конфигурация

Файл `.env` в корне репозитория (или `/opt/sanskrit_srv/.env`). Шаблон: [`.env.example`](../.env.example).  
Секреты **не коммитить**.

| Переменная | Обязательно | Назначение |
|------------|-------------|------------|
| `DATABASE_URL` | да | По умолчанию SQLite, напр. `sqlite:////opt/sanskrit_srv/data/sanskrit_srv.db` |
| `JWT_SECRET` | да | Длинная случайная строка для подписи токенов |
| `STORAGE_ROOT` | да | Каталог файлов проекта (сканы, PDF) |
| `CORS_ORIGINS` | нет | Список origin через запятую; `*` допустим на тестовом контуре |
| `GEMINI_API_KEY` | да* | Ключ [Google AI Studio](https://aistudio.google.com/apikey) (`*` нужен для LLM по умолчанию) |
| `GEMINI_API_KEYS` | нет | Дополнительные ключи Studio через запятую (`label:key`). На каждый free-tier — суточный лимит; исчерпанный пропускается до полуночи Калифорнии |
| `GEMINI_KEYS_FILE` | нет | Файл с ключами на сервере (не в git). Формат: ключ / метка / ключ |
| `GEMINI_BASE_URL` | нет | По умолчанию `https://generativelanguage.googleapis.com` |
| `GEMINI_MODEL` | нет | Модель **оцифровки** (скан). Не ставьте сюда `claude-*` |
| `GEMINI_TRANSLATE_MODEL` | нет | Модель **текстового** перевода / проверки перевода (не скан) |
| `TIMEWEB_API_KEY` | нет | Ключ [Timeweb AI Gateway](https://timeweb.cloud/docs/ai-agents/api-usage/ai-gateway) (маршрут Timeweb). Старое имя `OPENROUTER_API_KEY` ещё читается |
| `OPENROUTER_BASE_URL` | нет | По умолчанию `https://api.timeweb.ai/v1`; старый `openrouter.ai` подменяется на Timeweb |
| `TIMEWEB_MODEL` | нет | Id модели Timeweb из списка со зрением (напр. `gemini/gemini-3.5-flash`). Старое имя `OPENROUTER_MODEL` |
| `OPENROUTER_MAX_TOKENS` | нет | Лимит completion шлюза Timeweb |
| `OPENAI_API_KEY` | нет | Ключ ProxyAPI — нужен для маршрута Opus |
| `OPENAI_BASE_URL` | нет | По умолчанию `https://api.proxyapi.ru/openai/v1` |
| `OPENAI_MODEL` | нет | Модель OpenAI-канала, по умолчанию `gpt-4o-mini` |
| `ANTHROPIC_BASE_URL` | нет | По умолчанию `https://api.proxyapi.ru/anthropic` |
| `ANTHROPIC_MODEL` | нет | Claude на маршруте Opus (напр. `claude-opus-5`) |
| `LARGE_BOOK_PAGES` | нет | Порог подтверждения «оцифровать всю книгу» (по умолчанию `10`) |
| `DIGITIZE_BATCH_PAGES` | нет | Потолок страниц в одном вызове оцифровки (маршрут может взять меньше) |
| `TRANSLATE_BATCH_PAGES` | нет | Потолок страниц в одном текстовом вызове перевода |
| `DEFAULT_EXTRACT_MAX_PAGES` | нет | Устарело для upload (книга целиком); можно `0` |
| `LLM_PRICE_PER_1M` | нет | JSON тарифов USD/1M токенов для оценки $ в UI |

Пример оценки стоимости:

```bash
LLM_PRICE_PER_1M={"gemini:gemini-2.5-flash":{"in":0.1,"out":0.4},"openai:gpt-4o-mini":{"in":0.15,"out":0.6}}
```

Ключ: `сеть:модель`. Для ProxyAPI сверяйте тарифы вручную. Gemini AI Studio free-tier может использовать промпты для обучения моделей Google.

Приложение ищет `.env` в: текущий каталог → корень репозитория → `/opt/sanskrit_srv/.env`.

## 5. Бэкофис в UI

Роль **admin** → пункт **Бэкофис**. Четыре блока.

### Пользователи

Таблица: email, логин, имя, роль, активен, **Токены бэкофиса**, **Свои ключи**.

- Форма **Новый пользователь**: email, имя, логин (по умолчанию = email), пароль, роль, галочка **Разрешить токены и модель бэкофиса**.
- Колонка **Токены бэкофиса** — можно ли этому человеку брать ключи и маршрут из `.env` / блока «Маршрут LLM». Снятая галочка: только свои ключи в [кабинете](#6-кабинет-лк).
- **Свои ключи** — есть ли у пользователя сохранённые Timeweb / ProxyAPI (сам ключ в таблице не показывается).

### Расход токенов

1. Таблица **проект × сеть**: входящие (промпт) / исходящие (ответ) / всего / вызовы. Колонка **Задача** — оцифровка / перевод / IAST. У Gemini «всего» может быть больше суммы из‑за thinking.
2. Ниже — **по пользователям и ключам**: кто вызвал × свои ключи или токены бэкофиса (`key_source` + последние 4 символа ключа). Старые вызовы без пользователя — «бэкофис».

### Маршрут LLM

Переключатель без правки `.env` и без рестарта; пишется в `data/llm_route.json`. Список опций строится с сервера по наличию ключей:

- **Gemini (Google AI Studio)** — по умолчанию; скан уходит картинкой (`GEMINI_MODEL`), перевод текстом (`GEMINI_TRANSLATE_MODEL`);
- **Timeweb AI Gateway** — если задан `TIMEWEB_API_KEY` (или устаревший `OPENROUTER_API_KEY`); модель из списка со зрением: Gemini 3.5/3.6/3.7/3.8 Flash, Gemini 3.1 Pro Preview, Claude Opus 5 / Sonnet 5, GLM 5.3 Flash, Qwen 3.8 Max / 3.7 Plus / 3.6 Flash (без GLM 5.3 text-only и Qwen 3 Max с ответом 8K);
- **Claude Opus (ProxyAPI)** — Opus, запасные Gemini и OpenAI.

Выбор действует на оцифровку, перевод, IAST, пересмотр и смысловую проверку. Конкретные id моделей — в `.env`.

### Каталог LLM

Справочник id Timeweb (зрение) и ProxyAPI. Подсказка на экране: ключи Studio (`GEMINI_API_KEY` / `GEMINI_API_KEYS`), при необходимости Timeweb / ProxyAPI.

Загрузка PDF — на экране **Проекты** (только admin). Книги длиннее `LARGE_BOOK_PAGES` требуют подтверждения полной оцифровки.

## 6. Кабинет (ЛК)

Пункт **Кабинет** виден ролям **admin**, **expert**, **scholar**. Это личные настройки, не путать с бэкофисом.

| Блок | Что делает |
|------|------------|
| **Профиль** | Логин, email, имя. Смена email или пароля — только с текущим паролем |
| **Ключи LLM** | Галочка «Использовать токены и модель бэкофиса» (если admin разрешил). Иначе: ключ Timeweb и модель из списка со зрением, ключ ProxyAPI, выбор своей сети. **Вернуться к токенам бэкофиса** сбрасывает на маршрут сервера |
| **Мой расход токенов** | Только вызовы этого пользователя; свой ключ отдельно от токенов бэкофиса |

Если **Токены бэкофиса** сняты, галочка и кнопка возврата недоступны — без своих ключей LLM-кнопки в редакторе не пойдут.

## 7. Эксплуатация

| Задача | Как |
|--------|-----|
| Статус служб (VPS) | `systemctl status sanskrit-srv sanskrit-worker` |
| Логи | `journalctl -u sanskrit-srv -f` · `journalctl -u sanskrit-worker -f` |
| Health | `GET /health` → `{"status":"ok","service":"sanskrit_srv","version":"0.2.0"}` |
| Бэкап | Копировать `data/*.db` и дерево `storage/` при остановленном worker (или consistent snapshot) |
| Обновление кода | commit → `git push origin main` → GitHub Actions и/или rsync + `remote_deploy.sh`; `.env` / data / storage не трогать |
| Оцифровать несогласованные | В UI оцифровки (admin): только страницы без согласия. Согласованные не перезаписываются |
| Перевести / транслитерировать несогласованные | В проекте перевода или IAST (expert/admin). Шаблон правится кнопкой **Шаблон** → **Сохранить шаблон** |
| Смысловая проверка | На странице или **Проверить несогласованные**; маршрут LLM — бэкофис или ключи того, кто запустил |
| Слить переводы | На странице перевода: пустое поле под каждым `ru` → `POST /pages/{id}/merge-translations`. LLM собирает гибрид A (черновик) + B (вставка); сервер подменяет только совпавшую русскую строку по `॥ n ॥` / деванагари. Если строк в ответе меньше, чем на листе, и совпадения нет — 400, страница не затирается. Слоты в HTML не сохраняются |
| Голос переводчика | Таблицы `voices` / `voice_examples` (вне проекта). Проект: `settings.translation.voice_id`. API: `GET/POST /voices`, эталоны, `POST /voices/{id}/distill`. При translate/merge в промпт: style_card + top-k эталонов (лексический overlap). UI: список **Голос**, панель, **В голос** под шлокой |

Лимиты на слабом хосте: `MemoryMax` в unit-файлах (~400M API / ~550M worker). Большие книги (сотни страниц) гоняются **последовательно** и долго. Фильтр миниатюр «только несогласованные» — **только вид списка**; массовые кнопки и так не трогают согласованное.

## 8. Учёт LLM

Успешные вызовы LLM пишутся в БД с **пользователем** и признаком ключа (бэкофис / личный). В редакторе полоса **«Расход LLM»** (admin / expert / scholar) — по проекту. В **Кабинете** — только свои вызовы. В бэкофисе — проекты и разрез по ключам.  
Неуспешные HTTP не тарифицируются в учёте; локальный extract без LLM = 0.

## 9. Апгрейд сервера к 1.0

Текущий контур (~1 ГБ RAM, один воркер, SQLite) хватает для beta на тестовых книгах, но не для нагрузки 1.0: PDF-нарезка, экспорт большой книги и LLM-батчи упираются в RAM (`MemoryMax`) и в последовательную очередь.

**Shared-хостинг не подходит.** Нужен VPS (KVM, Ubuntu 24.04) с нашим `deploy/`. Ниже — заказной пресет Timeweb Cloud (витрина [VPS Linux](https://timeweb.cloud/services/vps-linux) / [VDS](https://timeweb.cloud/services/vds-vps), сентябрь 2026). Цены сверяйте перед оплатой: биллинг почасовой, на сайте указан месяц.

### Спецификация (рекомендуем)

| Параметр | Значение |
|----------|----------|
| Провайдер / регион | **Timeweb Cloud**, Москва (`ru-msk`) |
| Линейка | Premium NVMe, 3.3 ГГц, доля CPU 100% |
| **Тариф** | **Cloud-80** (на витрине также Cloud MSK 80) |
| vCPU | 4 × 3.3 ГГц |
| RAM | **8 ГБ** |
| Диск | **80 ГБ NVMe** |
| Канал | 1 Гбит/с |
| ОС | Ubuntu 24.04 |
| Сеть | 1 публичный IPv4 (в цене тарифа на витрине) |
| ПО | systemd: `sanskrit-srv` + `sanskrit-worker`; nginx/Caddy → `:8000`; без ispmanager |
| Firewall панели | входящие TCP **22**, **80**, **443** (порт 8000 снаружи не открывать) |
| SLA | 99,98% |

Зачем 8 ГБ / 80 ГБ: снять `MemoryMax` 400/550 M, пережить WeasyPrint на 600+ страницах, оставить место под PNG сканов. 50 ГБ на Cloud-50 для Mantra Pushpam (623 стр.) тесны.

### Стоимость в год (сервер)

Прайс витрины **1 800 ₽/мес** × 12 = **21 600 ₽/год** за сам Cloud-80.

| Статья | ₽/мес | ₽/год |
|--------|------:|------:|
| Cloud-80 (4 vCPU / 8 ГБ / 80 ГБ) | 1 800 | **21 600** |
| Доп. IPv4 (если понадобится второй) | 180 | 2 160 |
| Бэкап Timeweb, 1 хранимая копия диска | 6 ₽ × 80 ГБ = 480 | 5 760 |
| **Итого с одной копией бэкапа** | **2 280** | **27 360** |

Бэкап тарифицируется **за каждую лежащую копию** (не за факт создания). Семь суточных копий — 7 × 480 ₽/мес. Для SRV достаточно **1–2 копий** или своего архива `data/` + `storage/` на отдельный диск/S3.

Эконом-вариант, если остаёмся на одном воркере и чистим сканы: **Cloud-50** (2 vCPU / 4 ГБ / 50 ГБ) — **1 080 ₽/мес = 12 960 ₽/год**. Для 1.0 лучше Cloud-80.

Перенос: скопировать `.env`, `data/*.db`, `storage/`; git-rsync эти каталоги не трогает. После запуска поднять `MemoryMax` в unit-файлах. DNS A-запись поддомена (зона часто на Reg.ru) → новый IP. Старый ~1 ГБ VPS можно оставить под VPN.

Критерий **1.0**: полная книга (оцифровка + перевод или IAST + PDF/DOCX) без OOM и без ручных рестартов; бэкап по расписанию; HTTPS-only.

### LLM: Timeweb AI Gateway vs ProxyAPI

Цены Gateway — из панели Timeweb (сентябрь 2026); ProxyAPI — открытый прайс с НДС 5%. Все цифры: **₽ / 1 млн токенов, ввод / вывод**.

На моделях, которыми пользуется SRV, Timeweb **примерно в 2,2 раза дешевле** ProxyAPI. Каталог тот же (Gemini Flash/Pro, Claude Opus). Один счёт за VPS + LLM оправдан.

| Модель | Роль у нас | Timeweb Gateway | ProxyAPI | Timeweb / ProxyAPI |
|--------|------------|----------------:|---------:|-------------------:|
| **Gemini 3.5 Flash** | оцифровка | **203 / 1 215** | 455 / 2 730 | ~45% |
| **Gemini 3.1 Pro Preview** | перевод / IAST | **270 / 1 620** (контекст 1M, ответ до 66K) | 600 / 3 640 | ~45% |
| **Gemini 3.8 Flash** | новее Flash | **101 / 506** | 455 / 2 275 | ~22% ввода, ~22% вывода |
| **Gemini 3.7 Flash** | новее Flash | **101 / 506** | 455 / 2 275 | то же |
| **Gemini 3.6 Flash** | | **203 / 1 013** | 455 / 2 275 | ~45% |
| **Gemini 3.1 Flash Lite** | дешёвый текст | **34 / 203** | 76 / 455 | ~45% |
| **Claude Opus 5** | запасной маршрут | **675 / 3 375** | 1 516 / 7 579 | ~45% |
| **Claude 5 Sonnet** | запасной легче | **405 / 2 025** | 600 / 3 030 | ~67% |
| GPT-5.6 Luna | дешёвый GPT | 27 / 162 | 60 / 360 | ~45% |
| GPT-6 Astra | дорогой GPT | 1 350 / 6 750 | 1 580 / 7 900 | ~85% |

Gateway: OpenAI-совместимый API `https://api.timeweb.ai/v1`, ключ **1 ₽/мес**. В SRV это отдельный маршрут (вместо OpenRouter): тот же `/chat/completions`, ключ в `.env` (`TIMEWEB_API_KEY`) или в кабинете эксперта.

Как стыкуется с SRV:

- Бесплатный **Google AI Studio** (~20 запросов/день на ключ) по-прежнему дешевле любого платного шлюза — его можно оставить на оцифровку, пока хватает квоты.
- Платный контур выгоднее перевести на Timeweb, а не держать ProxyAPI: Flash 3.5, Pro 3.1 и Opus 5 все дешевле.
- Перед отключением ProxyAPI нужен **один пробный скан** через Gateway (картинка в chat completions). Если зрение Gemini проходит — один провайдер: Cloud-80 + Gateway. Если нет — VPS на Timeweb, оцифровка как сейчас через Studio.

Итого инфраструктура: сервер **21 600–27 360 ₽/год**; токены — отдельно, по факту, но прайс Timeweb для Gemini/Claude ниже ProxyAPI.

#### GLM 5.3 и Qwen (Timeweb Gateway)

Для SRV важны **зрение** (оцифровка скана) и **длинный HTML на выходе** (3–8 тыс. токенов на страницу).

| Модель | Timeweb | ProxyAPI | Зрение | К SRV |
