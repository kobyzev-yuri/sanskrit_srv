# Учёт токенов LLM (биллинг по проекту)

## Что считаем

Каждый **успешный** вызов ProxyAPI (HTTP 200) при черновике/пересмотре страницы пишется в таблицу `llm_usage_events`:

| Поле | Смысл |
|------|--------|
| `network` | Канал ProxyAPI: `gemini` или `openai` |
| `model` | Модель (`gemini-2.5-flash`, `gpt-4o-mini`, …) |
| `operation` | `auto_draft` (конвейер) или `revise` (эксперт) |
| `prompt_tokens` / `completion_tokens` / `total_tokens` | Из ответа API |
| `usage_raw` | Сырой usage/metadata для аудита |

Сводка: `GET /api/v1/projects/{id}/usage` — роли admin / expert / scholar.

## Что не считаем

- Локальный extract PNG / текстовый PDF без LLM → **0**
- Неуспешные HTTP (ошибка модели до ответа) → событие **не** пишется
- Ретраи другой модели после фейла → каждый **успешный** вызов отдельным событием (как у провайдера)

## Оценка $

Env `LLM_PRICE_PER_1M` — JSON USD за 1M токенов:

```bash
LLM_PRICE_PER_1M={"gemini:gemini-2.5-flash":{"in":0.1,"out":0.4},"openai:gpt-4o-mini":{"in":0.15,"out":0.6}}
```

Ключ: `network:model`. Нет цены → `est_usd=null` для строки; в `est_usd_total` только известные модели.

Цены нужно сверять с тарифами ProxyAPI и обновлять вручную.

## UI

В редакторе проекта полоса **«Расход LLM»**: токены, число вызовов, разбивка по сетям, оценка $.

## Ограничения

- Уже переведённые страницы **до** включения учёта в бэкфилл не попадают (usage не восстановить).
- Нет синхронизации с балансом ProxyAPI и нет инвойсов — только учёт по проекту.
